# Qalio｜客诉管理 Copilot

面向客服主管，把客服会话转为**可复核、有人负责、能够跟进到解决的客诉工单**。

会话分析 → 内容提炼与分类 → 风险分级 → 分派负责人 → AI 处置建议 → 人工确认与执行 → 回访与数据复盘。

## 产品闭环

~~~mermaid
flowchart LR
  A[会话导入] --> B[内容提炼与风险分级]
  B --> C[分派负责人并站内提醒]
  C --> D[检索规范与案例生成建议]
  D --> E[主管确认或更正]
  E --> F[人工执行与结案回访]
  F --> G[质量看板与高频问题复盘]
  F --> H[案例草稿审核发布]
  H --> D
~~~

当前为可运行的本地单用户 MVP：业务闭环已实现，平台自动同步和生产级隐私保护仍在规划中。

## 已实现

- **会话分析**：CSV 导入、核心诉求提炼、五类风险标签、P0/P1/P2 分级、原文证据。
- **两类判断分开**：投诉、退款和履约风险属于客诉信号；越权承诺、服务规范缺失属于客服违规线索。用户提出投诉，不直接等于客服违规。
- **自动分派**：风险会话生成工单，按优先级和问题类型分派岗位负责人，并产生持久化站内提醒；主管可转派。
- **处置建议**：检索已发布的服务规范和处理案例，保存知识版本及引用快照。可选 LLM 语义分析；默认本地规则与检索模板模式。
- **人工确认**：接受、修改或驳回风险；支持编辑处置方案；修改风险结论或驳回时须填写说明。未确认方案不能登记执行。
- **闭环工单**：待确认 → 待执行 → 处理中 → 已结案；保存实际处理结果、回访反馈、操作时间线。
- **数据复盘**：真实统计解决率、处理时长、逾期、风险分布、高频问题、负责人负载与反馈趋势，不再使用固定图表数字。
- **知识沉淀**：结案后生成案例草稿，可编辑和审核发布；新会话检索只使用已发布知识。
- **本地持久化**：SQLite 保存会话、复核、工单、知识与站内提醒；刷新或重启不丢失。

## 启动

Python 3.10+：

~~~bash
git clone https://github.com/wangfuwen/Qalio.git
cd Qalio
pip install -r requirements.txt
python -m uvicorn app:app --reload --host 127.0.0.1 --port 8000
~~~

打开 [主管工作台](http://127.0.0.1:8000)。首次启动自动载入 8 条模拟会话和 6 条演示知识，也可通过 [/insights](http://127.0.0.1:8000/insights) 进入数据复盘。

默认数据库为 data/copilot.sqlite3；可用 QA_DB_PATH 环境变量指定其他路径。请备份数据库文件保留工作成果。

| 环境变量 | 用途 | 默认行为 |
| --- | --- | --- |
| QA_DB_PATH | SQLite 数据库路径 | data/copilot.sqlite3 |
| QA_ENABLE_LLM | 是否调用外部模型 | 关闭；设置 true 或 1 开启 |
| OPENAI_API_KEY | 模型服务密钥 | 仅启用 LLM 时需要，勿写入仓库 |
| QA_MODEL | JSON 输出模型 | gpt-4o-mini |

### 启用 LLM

默认不调用外部模型，不需要 API 密钥。需要时在启动服务的终端显式配置：

~~~powershell
$env:QA_ENABLE_LLM="true"
$env:OPENAI_API_KEY="你的密钥"
$env:QA_MODEL="gpt-4o-mini"
python -m uvicorn app:app --host 127.0.0.1 --port 8000
~~~

QA_MODEL 可以设置为账号可用、支持 JSON 输出的模型。应用从进程环境读取配置；不会自动加载根目录 .env。已有会话保留分析快照，启用模型后对新导入会话生效。

启用后，新会话及检索到的知识内容会发送给模型服务。模型输出经结构、原文证据和知识 ID 校验；调用失败或校验不通过时回退规则。规则和模型发现不一致时保留有证据的发现并提示人工复核。规则没有统计意义上的置信度，界面不会展示虚构百分比。

当前知识检索采用本地标签匹配与关键词排序；这是可运行的轻量检索增强实现，尚未使用向量数据库或语义 embedding。

### CSV 格式

必填列：

~~~csv
conversation_id,date,agent,customer,dialogue
NEW-001,2026-09-04,客服小李,用户甲,"用户：三天没发货，我要投诉。\n客服：我来核实库存并反馈进度。"
~~~

支持 UTF-8 / UTF-8 BOM，真实换行或字面量 \n；日期使用 YYYY-MM-DD。单次最多 100 条、文件不超过 2 MB、单条会话不超过 20000 字。conversation_id 必须唯一；重复导入返回错误，不覆盖已有审批或工单。表头模板可在页面下载。

## 业务规则与指标

| 规则 | 当前实现 |
| --- | --- |
| P0 | 投诉专员，建单后 2 小时内处理 |
| P1 退款 | 售后负责人，24 小时 |
| P1 履约 | 履约负责人，24 小时 |
| 其他风险 | 质检主管，P2 为 72 小时 |
| 多种风险 | P0 优先，其次退款、履约；支持人工转派 |
| 工单解决率 | 已结案 / 未驳回工单 |
| 平均处理时长 | 建单到结案，包含等待主管确认时间 |
| 风险趋势 | 按会话发生日期统计；剔除已驳回风险 |
| 反馈趋势 | 按最新回访日期分组，使用每张工单当前反馈 |
| 数据缺失 | 无分母或无结案记录时显示「—」 |

处理期限从建单时间开始计算；人工调整等级时按原建单时间重新计算期限。岗位、时限和知识内容目前是演示配置，需按企业实际规范调整。

## 平台接入与隐私保护

目前仅支持 CSV 导入，**尚未接入淘宝、京东、抖音、企业微信等平台**。后续计划通过平台官方授权、消息回调或增量拉取接收会话，增加同步游标、消息去重、失败重试和企业归属校验。

当前实现的隐私边界：

- SQLite 中保存明文会话；尚无原文加密、自动脱敏、登录和企业/店铺权限隔离。
- 默认关闭外部模型；启用后，会话原文和召回知识会发送给模型服务。
- 已有处理时间线记录业务状态变化；尚不具备真实用户身份审计。
- 尚无自动保留期限、关联数据删除与备份清理机制。
- .env、本地数据库、复核运行记录、评测原始输出和浏览器测试截图被 Git 忽略。

因此当前版本面向模拟数据与技术验证，接入真实客户数据前需要补齐保护措施。具体设计和实施顺序见 [平台接入与隐私保护方案](docs/platform-integration.md)，该文档描述的是待实现能力。

## 当前边界

这是本地单用户 MVP。负责人是岗位，尚无登录、角色权限、多人身份审计或企业通讯录。提醒为站内记录；登记执行只记录人工业务动作，尚未对接退款、CRM、邮件或企业微信系统。内置会话、规范和案例均为模拟数据。

旧版 evaluation/ 的标签与结果面向客服话术违规，不等同于新版本的客诉风险和工单闭环；新版本尚未做真实业务数据或真实模型效果评测，不能沿用旧版分数。
