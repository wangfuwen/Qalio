# 平台接入与隐私保护方案

> 状态：设计方案，尚未实现。当前应用仍是 CSV 导入的本地单用户 MVP。

## 接入范围

逐个平台适配官方授权、消息回调或增量查询。首期选择一个平台、一个已授权店铺和必要文本消息，保留 CSV 作为历史补录入口。

具体可读范围、历史回溯窗口、消息类型及对外处理限制，以所选平台的接口权限和合同为准。供应商能够展示会话，不代表其允许向本应用提供全部原始会话。

## 建议数据流

~~~mermaid

  A[平台官方授权] --> B[回调接收或增量拉取]
  B --> C[验签、企业绑定、去重]
  C --> D[内部脱敏与必要字段筛选]
  D --> E[脱敏会话与有权访问的知识]
  E --> F[规则分析与可选模型]
  F --> G[主管确认与工单处置]
  C --> H[必要原文加密保存]
  H --> I[授权人员按需查看并留痕]
  G --> J[脱敏案例草稿]
  J --> K[人工审核发布]
~~~

## 连接层

- 按官方支持的方式授权，只申请必要读取权限；回复、退款等写入权限单独评估。
- 令牌保存在后端密钥管理服务或受保护的加密存储中，不出现在前端、日志和仓库；支持轮换和撤销。
- 验证回调签名，使用平台支持的时间戳或事件标识防重放；校验店铺与企业绑定关系。
- 以企业、平台、店铺和平台消息 ID 作为去重键，保存增量游标及同步状态。
- 消息可靠接收后确认回调，后台异步分析；失败重试、补拉和告警不在日志中记录原始会话或凭证。
- 区分消息与会话：同一会话持续接收新消息，按关闭事件或可配置静默窗口触发分析；保留分析版本，避免重复建单或覆盖已确认方案。
- 撤销授权后终止拉取，按保留策略处理已有数据。

## 原文、分析文本与知识

原文只在确有复核需要时保存，并限制访问。分析文本中的姓名、电话、详细地址和订单号替换为稳定代号，映射关系单独保护，不发送给模型。

脱敏结合格式规则和实体识别，并用漏检样本评测；不能仅依赖手机号正则。可关联回个人的代号属于去标识化，不能宣称已经完全匿名化。图片、语音和附件需要独立评估识别及脱敏链路，首期暂不自动处理。

知识库和检索索引同样需要企业隔离。结案案例应再次脱敏并经人工审核，禁止直接将客户原文作为通用知识发布。

## 模型调用边界

所有模型请求经过统一的数据出口检查，确认允许的字段、企业知识访问权限和脱敏结果。高敏感内容或无法可靠脱敏的内容转本地处理或人工复核。

企业可选择内部部署模型，或经审核的外部模型服务。外部服务的数据用途、留存、处理地区和分包关系需单独确认；不用于训练不等于不留存。内部部署也仍需身份控制、日志保护和访问审计。

模型不持有平台令牌，不自行扩大读取范围，不直接执行退款或消息发送。对话与知识条目始终作为不可信输入处理。

## 后端与数据生命周期

- 登录、会话管理、岗位权限及企业/店铺级数据授权必须由后端强制执行。
- 原文和备份加密，密钥与数据分离；系统管理员权限不默认等于业务原文读取权限。
- 审计记录访问人、对象、时间与动作，避免将原文复制进日志。
- 设置保留期限及删除流程，覆盖原文、映射、分析快照、案例、索引和备份生命周期。
- 平台授权、个人信息处理依据、告知与供应商责任需在真实接入前明确；技术措施不能替代企业对适用要求的确认。

## 当前实现与差距

| 能力 | 当前状态 |
| --- | --- |
| CSV 导入、规则分析、知识检索、人工确认、工单闭环 | 已实现 |
| LLM 开关、输出结构与证据校验、失败回退 | 已实现；真实模型未联调 |
| 平台授权、回调验签、增量同步与重试 | 未实现 |
| 登录、企业与店铺权限隔离 | 未实现 |
| 原文加密、字段脱敏、模型出口检查 | 未实现 |
| 实名操作审计、密钥管理、保留与删除策略 | 未实现 |

当前 SQLite 保存明文，现有处理历史是业务操作时间线，不是具有真实身份保障的安全审计。启用 LLM 会发送会话原文和召回知识，现阶段只应使用模拟或经过确认的测试数据。

## 建议落地顺序

1. 建立身份、企业归属和后端数据权限。
2. 增加脱敏、原文保护、密钥管理和审计。
3. 实现保留与删除机制、模型出口检查。
4. 选择一个有官方授权的平台，完成隔离测试环境接入。
5. 验证重复回调、断线补拉、撤权、越权访问及隐私泄露用例。
6. 小范围试运行，评估消息完整性、风险误报和处理效果后扩展渠道。
