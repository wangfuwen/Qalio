# 重构说明

## 从质检页面到业务闭环

原版 app.py 在每次查询时重新按关键词分类样本，上传结果仅返回前端，复核只追加 JSONL。洞察页中的趋势与比例是静态内容。

新版以持久化会话为中心，每条风险会话关联一张工单、分析证据、知识快照和处理历史。API 使用 SQLite 事务检查状态并写入结果，重复导入和重复审批不会覆盖已有业务状态。

## 状态流转

~~~mermaid
flowchart LR
  A[会话导入] --> B[内容提炼与风险分类]
  B --> C[生成工单并分派负责人]
  C --> D[待主管确认]
  D -->|接受或更正并确认方案| E[待执行]
  D -->|驳回并说明原因| X[已驳回]
  E --> F[登记开始执行]
  F --> G[记录处理结果与回访]
  G --> H[已结案]
  H --> I[生成案例草稿]
  I --> J[编辑及审核发布]
  J --> K[知识检索]
  K --> D
  H --> L[数据复盘]
~~~

未命中规则的会话也保留，可人工抽检；主管补充风险标签与等级后可创建工单。已确认方案是独立快照，后续知识发布不会改写历史方案。已发布条目不能直接修改；修订时新建版本，历史引用保持可追溯。

## 分析结构

1. 对话归一化：兼容字面量换行，区分用户与客服发言。
2. 规则：识别越权承诺、退款、履约、投诉升级、服务规范缺失；简单否定表达过滤。复杂语义仍需人工复核。
3. 检索：在已发布条目中按标签交集和标题关键词排序，最多召回 4 条。
4. 可选 LLM：将会话和召回知识作为数据输入，提炼诉求、补充有原文证据的发现并生成建议。
5. 校验：检查结构、风险标签、逐字证据、客服违规证据的说话人以及知识引用 ID。失败回退规则，不输出未经校验的模型结论。
6. 人工确认：原始分析、知识快照与当前主管结论并存，执行只使用主管确认后的方案。

引用 ID 校验不代表建议内容已经被事实核验；主管仍须核对订单、实际政策与权限。模型发现与规则不一致时保留证据并明确提示。

本地模式使用规范生成处理步骤，同时展示相关历史案例。高频优化建议为按标签生成的规则化建议，不将标签频率称作因果分析结论。

## 数据和迁移

- SQLite 的 conversations、knowledge、notifications 表保存 JSON 业务记录。
- 初始化标记保证样本和演示知识只载入一次。
- 数据库路径可通过 QA_DB_PATH 覆盖；自动化测试使用临时路径。
- CSV 导入先全量校验和分析，再事务落库，避免部分导入。
- 旧 data/review_feedback.jsonl 没有审批方案和执行信息，因此不自动转换成已批准工单。若存在该文件，会保留原文件，需核对后再迁移。
- 旧评测文件保持原样，不混用客服违规与客诉处理风险的定义。

## 浏览器验收

tests/browser_smoke.cjs 覆盖总览展示、可见错误提示、确认方案、开始执行、结案、案例编辑发布、指标刷新和移动端布局。

必须连接全新的隔离测试数据库，测试会修改 C001 的工单状态。不要对正式工作台数据库运行：

~~~powershell
pip install -r requirements-dev.txt
npm install --no-save --package-lock=false playwright
npx playwright install chromium
$env:QA_DB_PATH = Join-Path $env:TEMP ("qalio-smoke-" + [guid]::NewGuid().ToString() + ".sqlite3")
$env:QA_ENABLE_LLM = "false"
python -m uvicorn app:app --host 127.0.0.1 --port 8765
~~~

在另一个终端执行：

~~~powershell
node tests/browser_smoke.cjs
~~~

可通过 QA_BASE_URL 改变测试地址，或用 QA_BROWSER_EXECUTABLE 指定本地浏览器可执行文件。截图保存在 data/workspace-preview.png 和 data/mobile-preview.png，不纳入 Git。
